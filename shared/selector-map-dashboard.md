## Temuan Struktural Penting (perbedaan vs dokumen lama — DILAPORKAN APA ADANYA)

1. **Layar Monitoring live TIDAK PUNYA peta sama sekali** — kontras total dengan `explore/module-map.md` baris #1 ("Dashboard (peta + statistik)... kontrol Perbesar/Perkecil, Layar Penuh, filter 'Semua Customer'/'Semua Kasus'"), catatan itu berasal dari run 2026-08-22 dan sudah usang. Live sesi ini: `browser_find` untuk regex `/peta|map|Layar Penuh|Perbesar|Perkecil|Semua Customer|Semua Kasus/i` di `/monitoring` = **0 match**. Layar live justru cocok 1:1 dengan `oms2324-dashboard.analysis.md` UI Inventory "Layar Monitoring" (REQ-001–005): 2 score card (Total Armada, Melewati SLA), 5 filter chip tahapan, search + refresh, list card "Daftar Armada Berjalan", pagination. **Kesimpulan: dokumen scenario (`oms2324-dashboard`) sudah akurat mengikuti live, `module-map.md` yang basi** — perlu update `module-map.md` baris #1 terpisah.
2. **Link "Riwayat" TIDAK ADA di halaman Monitoring** (`browser_find` teks "Riwayat" di `/monitoring` = 0 match), tapi **route `/monitoring/riwayat` tetap hidup dan reachable via direct URL** (judul tab "Riwayat Kasus", breadcrumb "Beranda / Monitoring / Riwayat Kasus", link "← Kembali" balik ke `/monitoring`, 377 data). Ini pola sama seperti "Edit Penugasan tanpa entry point UI" (`shared/selector-map-penugasan.md` Temuan penugasan) — kemungkinan tombol/link trigger di UI dihapus/belum dipasang, tapi backend route & halamannya utuh. Perlu triase apakah ini regresi atau memang halaman deprecated.
3. **Link "Lacak" (ke `/tracking-location?orderCode=...`) TIDAK ADA** — konsisten dengan Temuan #6 di bawah (`/tracking-location` hilang total dari sidebar, entitlement-gated). Aksi per-card di Monitoring sekarang HANYA "Detail" → `/penugasan-tracking/{uuid}` (Detail Penugasan), BUKAN ke halaman tracking terpisah. Ini sesuai REQ-005 `oms2324-dashboard.analysis.md` ("Aksi Detail... membawa user ke halaman detail penugasan"), jadi scenario doc sudah benar, hanya `module-map.md` yang basi.
4. **Dashboard Operasional & Distribusi & Muatan TERNYATA JAUH LEBIH KAYA** dari catatan lama `module-map.md` baris #4 ("Filter periode, dropdown Tipe Order, Export"). Live Operasional (`/dashboard-operasional`) punya 3 section besar: **Volume dan Aktivitas** (Total Order + donut Jenis Pengiriman FTL/FCL/LTL/LCL + line chart Tren Volume Order mingguan), **Produktivitas Vendor** (Total Vendor Digunakan, Rata-rata Trip per Vendor, tabel "5 Vendor Paling Produktif"), **Performa Pengiriman** (Jumlah Order Tepat Waktu/Terlambat, donut Ketepatan Waktu, tabel sortable "Daftar Keterlambatan Pengiriman" dengan search + **modal "Detail Keterlambatan"** per baris berisi tabel ID Order/Tanggal Muat/Keterangan + chart "Tren Keterlambatan"). Ini tidak tercakup sama sekali di `oms2324-dashboard.analysis.md` (yang hanya menyebut REQ untuk Distribusi & Muatan, TIDAK ada REQ eksplisit untuk konten Operasional) — **gap dokumentasi scenario**, bukan cuma `module-map.md`.
5. **Dashboard Distribusi & Muatan (`/dashboard-distribusi`) — layar yang belum pernah dipetakan sebelumnya, sekarang terkonfirmasi cocok BAIK dengan spec REQ-006/007/008 `oms2324-dashboard.analysis.md`**: filter periode Harian/Mingguan/Bulanan/Tahunan/Pilih Tanggal (default **Bulanan** dikonfirmasi via class CSS `border-brand-500 bg-brand-500 text-white`, TIDAK ada `aria-pressed` — state aktif murni visual, lihat Temuan #7), tombol Export; section **Jangkauan Distribusi** (3 score card Kota Terjangkau/Jumlah Pengirim Aktif/Jumlah Penerima Aktif + peta choropleth Indonesia dengan legend "Jumlah Order" 5 tingkat warna, dropdown Kota Asal/Kota Tujuan default **Kota Tujuan (Penerima)**, kontrol Perbesar/Perkecil/"Pas-kan tampilan ke seluruh Indonesia" — BUKAN "Reset"/"Fit" seperti dugaan lama); section **Utilitas Armada** (3 score card Rata-rata Barang per Pengiriman/Pengiriman <50% Kapasitas/Kelebihan Muatan + chart horizontal "Profil Barang Terkirim" per jenis barang + 2 progress bar "Tingkat Keterisian Armada": Keterisian Ruang (Volume) & Keterisian Barang (Berat/Tonase), pakai native `<meter>` element dengan accessible name lengkap format `"<Label> <N> persen"`).
6. **`Dashboard ▸ Tracking & Location` (`/tracking-location`) dikonfirmasi ULANG hilang dari sidebar** (submenu Dashboard di semua 4 halaman yang dipetakan sesi ini konsisten hanya 3 item: Monitoring, Operasional, Distribusi & Muatan) — reproduce langsung temuan `explore/module-map.md` 2026-09-07 (entitlement live = OMS-only). Tidak dipetakan lebih lanjut (di luar cakupan modul `oms2324-dashboard`, dan tugas eksplisit melarang memaksa via direct URL).
7. **Filter chip/tombol aktif (periode Operasional/Distribusi & tahapan Monitoring) TIDAK exposed via ARIA** (`aria-pressed` selalu `null`) — state aktif hanya bisa dideteksi lewat class CSS Tailwind (`border-brand-500 bg-brand-500 text-white` vs default `border-gray-200 bg-white text-gray-600`). Sama pola dengan tombol filter chip lain di aplikasi (mis. Monitoring "Semua Tahapan" dkk) — assertion executor untuk "chip aktif" harus pakai `toHaveClass(/brand-500/)`, bukan role/state ARIA.
8. **Peta choropleth (Distribusi & Muatan) render sebagai `<img role="img">` bertitle dinamis** `"Peta sebaran order per wilayah — <Kota Tujuan (Penerima)|Kota Asal (Pengirim)>"` — accessible name berubah otomatis mengikuti dropdown (dikonfirmasi hands-on: ganti dropdown ke "Kota Asal (Pengirim)" → title img berubah seketika, lalu direset balik ke default). Ini **bukan** peta interaktif SVG/canvas biasa dengan region per provinsi yang bisa diklik individual — provinsi & angka ditampilkan sebagai teks list di dalam wrapper gambar (`generic` nodes), bukan `getByRole('button')`/`option` per provinsi.
9. **Notifikasi bell (badge count, header)**: tombol TIDAK punya `aria-label`/`title` sama sekali — accessible name = angka badge itu sendiri (live: `"63"`), yang berubah seiring waktu. **TIDAK STABIL sebagai selector** (mis. `getByRole('button', {name:'63'})` akan basi begitu ada notifikasi baru) — rekomendasi developer: tambah `aria-label="Notifikasi"` tetap terpisah dari teks badge.
10. **Pagination (Monitoring & Riwayat Kasus) pakai pola sama seperti `shared/selector-map-penugasan.md`**: tombol icon-only tanpa `aria-label`, accessible name berasal dari atribut HTML `title` (`"Halaman pertama"`, `"Sebelumnya"`, `"Berikutnya"`, `"Halaman terakhir"`) — `getByRole('button', {name:...})` tetap valid karena browser mengambil accessible name dari `title`.
11. **Aplikasi tetap tidak punya `data-testid` sama sekali** di seluruh 4 layar yang dipetakan (konsisten dengan temuan modul Order & Penugasan Tracking sebelumnya). Beberapa `id` auto-generated React ditemukan (`dp-_r_0_`, `dp-_r_1_` pada date range picker "Tanggal Kasus Dari/Sampai" di Riwayat Kasus) — TIDAK STABIL, pola sama seperti Riwayat Perubahan Penugasan.

## Rekomendasi data-testid untuk developer

- `data-testid="score-total-armada"` / `"score-melewati-sla"` (Monitoring) — score card `getByText` rawan salah-match dengan filter chip bertulisan sama (Melewati SLA muncul 2x di halaman: score card & filter chip).
- `data-testid="filter-tahapan-<slug>"` pada 5 filter chip Monitoring, plus `aria-pressed` yang benar-benar reflect state aktif (saat ini hanya class CSS, tidak accessible — Temuan #7).
- `data-testid="card-armada-<idOrder>"` pada tiap card Daftar Armada Berjalan — saat ini harus di-scope manual via teks ID Order yang panjang.
- `data-testid="link-riwayat-monitoring"` bila link "Riwayat" memang dimaksud tetap ada di UI (Temuan #2) — saat ini hilang total dari halaman meski route-nya hidup; perlu klarifikasi produk apakah ini regresi.
- `aria-label="Notifikasi (<n> baru)"` pada tombol bell header (Temuan #9) — saat ini accessible name adalah angka badge itu sendiri, sangat tidak stabil untuk assertion.
- `data-testid="chip-periode-<slug>"` pada 5 chip periode (Harian/Mingguan/Bulanan/Tahunan/Pilih Tanggal) di Operasional & Distribusi & Muatan, dengan `aria-pressed` yang benar (Temuan #4/#7) — dipakai 2x di 2 halaman berbeda, penting untuk skenario default-periode (REQ-006).
- `data-testid="map-jangkauan-distribusi"` pada elemen peta choropleth (Temuan #8) — saat ini `role="img"` dengan title dinamis, sulit di-assert bagian dalam (provinsi/angka) karena semua konten peta ada di dalam wrapper `<img>`-like tanpa role granular per provinsi.
- `data-testid="dropdown-lokasi-peta"` pada select Kota Asal/Kota Tujuan (Distribusi & Muatan) — saat ini generic `getByRole('combobox')`, berisiko tidak unik bila halaman lain punya select serupa.
- `data-testid="modal-detail-keterlambatan"` pada modal/panel Detail Keterlambatan (Operasional) — untuk membedakan dari elemen section utama yang share heading level sama.
- `data-testid="filter-kasus-riwayat"` pada dropdown "Pilih Kasus" (Riwayat Kasus) — sesi ini tidak berhasil dibuka karena overlay lain berulang kali intercept klik; `data-testid` + memastikan tidak ada elemen overlap akan mempermudah automation.
